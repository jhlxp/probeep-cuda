## 2. 阶段职责

| 阶段 | 输入 | 输出 | 是否进入正式时延 |
|---|---|---|---:|
| `workload/` | 只读 `workload/raw_data1` | 精确 TopK route、SHA、case plan | 否 |
| `setup/` | 本 Test 私有 env 与 launcher | H20/RDMA preflight、extension build、import provenance | 否 |
| `correctness/` | 同一源码与拓扑 | DeepEP、MoonEP、ProbeEP、UltraEP smoke；ProbeEP forward/backward/expert-I/O | 否 |
| `correctness/observation-synthetic/` | 合成六元 observation | controller consumer 与 A/M 隔离证据 | 否 |
| `benchmark/` | manifest、plan、真实 scheduler/device events | 五算法双 microbatch HT 的正式 CSV/JSON | 是 |
| `nsys/` | 与 benchmark 相同源码和配置 | `.nsys-rep`、SQLite、NVTX/kernel/API stats | 否 |
| `artifacts/` | `benchmark/raw/` | 按算法、按 Layer 的自包含 HTML/CSV/JSON 目录及其镜像 ZIP | 派生结果 |

真实 Attention/MoE observation producer 的证据必须写入 `benchmark/raw/`。合成
observation 只写入 `correctness/observation-synthetic/`，不能用来替代正式闭环。

## 3. Benchmark 原始产物

| 文件 | 口径 |
|---|---|
| `raw/benchmark_status.jsonl` | 每个 backend/layer/repeat 的启动、完成和失败状态 |
| `raw/correctness.jsonl` | timed 前的数值正确性检查 |
| `raw/iterations.csv` | 每个 measured iteration 的跨 rank critical-path 时间 |
| `raw/rank_samples.csv` | 每算法每 rank 的 home/raw/padding 负载 |
| `raw/expert_samples.csv` | E256 每个 routed expert 的 receive rows |
| `raw/rank_expert_samples.csv` | 每算法 `(rank, expert)` 的 raw/padded grouped-FFN rows |
| `raw/microbatch_rank_samples.csv` | 每个 measured iteration 的 MB0/MB1 逐 rank home/execution/padding rows；两个 microbatch 独立出图，不合并柱图 |
| `raw/microbatch_timeline.csv` | 每个 measured iteration、rank、logical stream 的 CUDA-event `start_ms/end_ms/duration_ms`；W+D 是 communication stream 实际 active interval，A/M controller 另取 compute-release→W+D-done；ProbeEP 额外记录 observation producer，不伪造独立 controller interval |
| `raw/rdma_path_load.csv` | 五算法、两个 MB、每轮所有有向 logical rail 的 physical NIC/subrail、200-Gbps cap、runtime unit、Dispatch、cache-miss Weight、weight version/cache mode 与 TX/RX；零流量 rail 也保留 |
| `raw/probeep_observation_samples.csv` | controller 本层实际消费的上一层同 round A/M observation；显式记录 producer/consumer layer、repeat、round、dispatch/compute microbatch 与逐 rank compute/network ns/byte counters |
| `raw/probeep_plan_summary.jsonl` | production CUDA planner 的 budget、intent、admission、invariants、phase cycles 和完整 chunk table |
| `raw/probeep_weight_chunks.csv` | 逐 expert、逐 offset、逐 rail 的 production Weight chunk；`transfer_required` 区分规划 chunk 与实际传输，用于分色和聚合守恒检查 |
五个算法必须共享 workload manifest、layer route SHA、拓扑、dtype、双 microbatch 调度和
计时边界。同一算法的多个 layer/repeat 可以写入同一 `benchmark/raw/`，但不得跨 Test
或跨 Slurm job 追加。

Test 01 fresh run 的固定门禁为：`microbatch_timeline.csv=131200` 行、
`rdma_path_load.csv=32000` 行、`probeep_observation_samples.csv=6080` 行；Layer 00 使用明确 bootstrap，不写伪 observation。
`probeep_weight_chunks.csv` 行数随真实 admission/cache 状态变化。rail 文件是 runtime
routing/count 生成的逻辑 payload 账本，不是 NIC 硬件计数；采集位于 timed 区间之后。

raw、导出 CSV 与 HTML 必须通过同一组跨文件守恒门禁：

| 对齐关系 | 必须满足 |
|---|---|
| rank ↔ microbatch | 每个 rank 的合计 `home/exec` 分别严格等于 MB0+MB1；NCCL/DeepEP 的每个 MB 都保持 `exec=home` |
| timeline ↔ DAG | 每个算法、Layer、Round、rank 的真实 CUDA-event interval 完整，并逐边满足实际 stream/event 依赖 |
| rail 内部 | 每行 `TX=Dispatch+Weight=RX`，且 Dispatch bytes 与 runtime unit/count 严格一致 |
| plan ↔ chunk ↔ rail | ProbeEP 每个 A/M plan 的 chunk 数一致；实际 chunk bytes 按 source/destination rail 求和后严格等于 rail Weight bytes 和 plan TX/RX admission |
| observation ↔ 上一层 | Layer L 消费的 A/M 每-rank Dispatch/Weight counters，严格等于 Layer L−1、同 Round、同 chain 的 rail producer；A/M 不交叉 |
| HTML ↔ 导出 CSV | 页面只读取本算法、本 Layer、本 microbatch 的记录；导出 rail/chunk CSV 保留 round、A/M、NIC/subrail、cache/version 等追溯字段 |

任一关系失败，正式 Test 在生成可引用报告前终止；可视化不能通过重算或补值掩盖 raw
错误。

## 4. Nsight Systems

每个 profile target 使用 `nsys/<target>/` 独立子目录，防止同名 report 覆盖。

| 内容 | 规则 |
|---|---|
| `.nsys-rep` | 保存原始 timeline |
| `.sqlite` | 与对应 report 同目录 |
| `*-nvtx_gpu_proj_sum*` | 检查 planner/Weight/Dispatch/FFN/Combine 范围 |
| `*-cuda_gpu_kern_sum*` | 检查 kernel 时间与新增瓶颈 |
| `*-cuda_api_sum*` | 检查 host sync、allocator 和异常轮询 |
| `*-cuda_gpu_mem_time_sum*` | 检查意外 memcpy/memset |

nsys 时延不进入 `benchmark/result.json`。自动 overlap 摘要只作诊断，最终依赖关系仍以
timeline 中的 stream/event 边为准。

`nsys/formal-pipeline/nsys/` 额外保存每节点 `*-overlap.json` 和 `*-overlap.txt`。顶层
验收会检查每节点 `.nsys-rep`、SQLite 和非空 measured iteration，缺失即判 Test 不完整。

## 5. 分层自包含 HTML ZIP

Test 01 的 `raw_data1_layers_00_19_by_algorithm_rounds_11_20_mean.zip` 必须完整镜像同名
报告目录。入口为 `algorithm_comparison.html`，再按“算法 → Layer”进入单层页面。

| 检查 | PASS 条件 |
|---|---|
| 算法入口 | 5 个且只对应本 Test 的五算法 |
| Layer 页面 | 每算法 20 个，共 100 个独立页面；任何页面只含一个 Layer |
| 页面顺序 | 严格时间戳流水线/DAG → Microbatch 1 全部 → Microbatch 2 全部 → 十轮原始表 |
| microbatch 图 | 每个 batch 各自画原始/调度后 rank、server-pair、per-rail/NIC；禁止 MB0+MB1 合计柱图 |
| traffic 堆叠 | 每条 rail 严格为 `[Token Dispatch bytes][Expert Weight bytes]`，Expert 从 Token 末尾继续且不得覆盖；fresh raw 的 Expert 段再按 expert id 细分，旧 raw 只有聚合值时为青色 |
| 外部依赖 | 无 CDN、无外链脚本 |
| 原始数据 | 每个 Layer 自带 JSON/CSV；ZIP 与目录成员集合完全一致 |
| 完整性 | `ZipFile.testzip()` 返回 `None` |

严格时间线只读取实测 CUDA-event `start_ms/end_ms`；缺少该 CSV 时页面明确显示“无时间戳
证据”，不能从合计 phase latency 反推。DAG 区分同 stream 顺序、跨 stream event wait、host
完成边界与跨轮 feedback。没有实测 active time 时
rail 图只展示 bytes，不用标称带宽推算“实测”goodput。

| DAG 边 | 真实含义 |
|---|---|
| `P/W/D0→P/W/D1→C0→C1` | communication stream 提交顺序；controller 在对应 `P/W/D` 内融合 |
| `A/G0→A/G1→E0→E1` | default compute stream 的业务计算提交顺序 |
| `A/G0→D0`、`A/G1→D1` | routing-ready CUDA event；形成 `A1∥W+D0` 与 `E0∥W+D1` 的前提 |
| `D0→E0`、`D1→E1` | dispatch-ready CUDA event |
| `E0→C0`、`E1→C1` | expert-done CUDA event |
| `E0→P/W/D1` | 仅单 replica-weight bank 的 DeepEP-MoonEP / UltraEP+HybridEP |
| `A1 + W/D0→A[L,r]` | Attention observation 的两个独立数据源 |
| `E0 + W/D1→M[L,r]` | MoE observation 的两个独立数据源 |
| `C1→feedback_prepare` | 本轮结束后物化两条 feedback；只表示执行顺序，不合并 A/M 状态 |
| `A[L,r]→MB0 P/W/D[L+1,r]` | 跨层 Attention feedback；只更新/消费 `B_attention` |
| `M[L,r]→MB1 P/W/D[L+1,r]` | 跨层 MoE feedback；只更新/消费 `B_moe` |

## 7. 作废条件

| 情况 | 处理 |
|---|---|
| 缺五算法任一项 | 整个 Test benchmark 作废 |
| 任意 layer 的 routing SHA 不一致 | 作废 |
| Test 01 数据冒充 Test 02 | 作废 |
| nsys/profile 时延混入正式结果 | 作废 |
| 合成 observation 冒充真实闭环 | 作废 |
| ZIP 与分层报告目录成员不完全一致、缺五算法/Layer 页面或 CRC 失败 | 作废 |
| setup、correctness、benchmark、nsys 或 artifacts 搬到其他平级 run | 目录验收失败 |

清理以整个 Test 顶层 `run_*` 为单位，不拆分保留有利阶段。
